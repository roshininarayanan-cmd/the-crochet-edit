I'm building The Crochet Edit, a visual crochet inspiration library because I regularly discover patterns and project ideas on Pinterest, Instagram, and YouTube but want one place to save and revisit them when making gifts and personal projects. I expect to use it several times a week, and incredibly often during the holidays, to collect ideas and choose my next project for my relatives. Other crocheters can create accounts and manage their own collections.
Features 1. Sign up and login: As a crocheter, I want to create an account within the app and sign in and out so my library stays private and returnable. Creating an account also creates a row in the app's users table 2. Data model: As a crocheter, I want each idea assigned to one of my categories (Plushies, Clothing, Bags, Accessories, Home Decor, or Gifts) so I can organize inspirations. Categories belong to individual users. 3. CRUD for inspirations: As a crocheter with many ideas, I want to add an inspiration with a title, category, optional photo/pattern URL, difficulty, and notes; see a gallery; open a detail page; edit an idea; and delete it after confirmation so my collection remains useful and relevant. 4. Validation: As a crocheter, I want clear messages when I try to upload an inspiration without a title or category so I know what to fix when submitting. 5. Stars: As a crocheter, I want to star and unstar inspirations and see a dedicated favorites page so I can prioritize projects. Each star is a row in a shared stars junction table linked to a user and inspiration, with no duplicate pair. 6. Find and sort: As a busy student who spends free time crocheting, I want to search by title or notes, filter by category and difficulty, and sort newest or oldest so I can quickly find an idea. 7. Dashboard: As an avid crocheter, I want to see total saved inspirations, total starred inspirations, and total completed inspirations plus a bar chart of inspirations by category so I can understand my collection. 8. Photo upload: As a crocheter, I want to upload a JPG or PNG file from my device and see it in my gallery so I can save visual inspiration. Files are stored persistently, with access controlled per user. 9. Project status: As a crocheter, I want to mark projects Want to Make, In Progress, or Completed and change status from an idea's detail page so I can track my progress. 10. Surprise Me: As a crocheter interested in trying new projects, I want a button that randomly selects one of my own saved inspirations so I can decide what to make next, and will show a friendly empty state message if none exist. 
users — id (text, PK, Clerk user ID); email (text, unique, required); created_at (timestamp). Create/synchronize a row after account registration/login; Clerk handles password credentials, and our database stores an app-specific user record. categories — id (UUID, PK); user_id (text, required, FK to users.id); name (text, required); created_at (timestamp). One user has many categories. Category names are unique per user. inspirations — id (UUID, PK); user_id (text, required, FK to users.id); category_id (UUID, required, FK to categories.id); title (text, required); pattern_url (text, optional); image_key (text, optional storage reference); difficulty (text, optional: Beginner/Intermediate/Advanced); notes (text, optional); status (text, required, default Want to Make; allowed values Want to Make/In Progress/Completed); created_at and updated_at (timestamps). One user and one category each have many inspirations. stars — user_id (text, required, FK to users.id); inspiration_id (UUID, required, FK to inspirations.id); created_at (timestamp). Composite primary key: (user_id, inspiration_id). One user can star many inspirations and an inspiration can have many stars; this is a many-to-many junction table. Only a user who owns an inspiration may star it in this private-library version.

AI coding agent: Replit Agent, because I can build and preview the app in the same workspace while reviewing the AI-generated code. Frontend: React + TypeScript, to build reusable gallery cards, forms, and detail pages with typed data. Backend: Node.js + Express, to handle authenticated requests, validation, database operations, and file access. Database: Replit-managed PostgreSQL with Drizzle ORM, for durable relational data and explicit foreign-key relationships. Authentication: Replit-managed Clerk Auth with in-app email/password registration, login, and logout; a synchronized app-level users row is also required. Photo storage: Replit App Storage, to persist uploaded images instead of saving them to the temporary app filesystem. Hosting: Replit Publishing, because it is integrated with the workspace and can run the frontend, backend, and production database.
